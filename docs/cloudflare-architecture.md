# Cloudflare-এ আসল সফটওয়্যারের কাঠামো

লক্ষ্য: প্রতিটা ক্লায়েন্টের নিজের লগইন, একটা অ্যাডমিন প্যানেল, ক্লায়েন্টের পিসি থেকে যেকোনো প্রিন্টারে প্রিন্ট, আর পরে একই ব্যাকএন্ড দিয়ে APK।

## ১. সবচেয়ে বড় প্রভাব: D1 মানে SQLite, PostgreSQL নয়

এ পর্যন্ত লেখা `schema.sql`, `logic.sql`, `sync.sql`, `returns.sql`, `recipes.sql` PostgreSQL ধরে লেখা। D1-এ এগুলো সরাসরি চলবে না:

| PostgreSQL-এ ছিল | D1 (SQLite)-এ কী হবে |
|---|---|
| plpgsql ফাংশন (`create_sale`, `sell_fefo`...) | সার্ভারের কোডে (TypeScript, Cloudflare Worker) |
| `BEGIN ... COMMIT` ট্রানজেকশন | `db.batch([...])`: ব্যাচের সব স্টেটমেন্ট একসঙ্গে সফল হয় বা কিছুই হয় না |
| `bigserial` আইডি | অ্যাপে তৈরি টেক্সট আইডি (ULID/UUID) |
| `numeric(14,2)` | পূর্ণসংখ্যা (নিচে দেখুন) |
| `FOR UPDATE` লক | দরকার নেই: একটা D1 ডাটাবেস একবারে একটা কোয়েরি চালায় |
| `ASSERT` টেস্ট | Vitest টেস্ট, একই দৃশ্যগুলো নিয়ে |

**যা বাঁচে:** পুরো নকশা, টেবিলের কাঠামো, স্টক লেজারের নিয়ম, FEFO, `client_uuid` দিয়ে দুবার জমা আটকানো, পর্যালোচনার চিহ্ন, ফেরত, রেসিপি। আগের SQL ফাইলগুলো এখন **স্পেসিফিকেশনের কাজ** করবে, আর টেস্টের দৃশ্যগুলো নতুন কোডে ব্যবহার হবে। ফাইলগুলো এখনো কোনো ডাটাবেসে চালিয়ে পরীক্ষা করা হয়নি।

## ২. কাঠামো

```
ক্লায়েন্টের পিসি/ফোন (ব্রাউজার, পরে APK)
        │  HTTPS
        ▼
Cloudflare Pages ── স্টাফ অ্যাপ (PWA)   /app
                 └─ অ্যাডমিন প্যানেল     /admin
        │  /api/*
        ▼
Cloudflare Worker (Hono, TypeScript)
   • লগইন ও সেশন   • স্টক/বিক্রি/ফেরত/রেসিপির লজিক
   • প্রতিটা কোয়েরিতে shop_id বাধ্যতামূলক
        │
        ├─ D1 (মূল ডাটাবেস)
        ├─ R2 (ব্যাকআপ ফাইল, লোগো)
        └─ Cron Trigger (রোজ ব্যাকআপ, মেয়াদ শেষ হওয়া অ্যাকাউন্ট বন্ধ)
```

## ৩. প্রতিটা ক্লায়েন্টের আলাদা অ্যাকাউন্ট

**সুপারিশ: একটা D1 ডাটাবেস, প্রতিটা টেবিলে `shop_id`** (আমাদের স্কিমায় আগে থেকেই আছে)।

- একটা ডাটাবেসে সব ক্লায়েন্ট রাখলে নতুন ক্লায়েন্ট যোগ করা মানে শুধু একটা সারি, কোনো ডিপ্লয় লাগে না।
- ক্লায়েন্টপ্রতি আলাদা D1 ডাটাবেসও সম্ভব, কিন্তু প্রতিটা Worker-এ আলাদা বাইন্ডিং যোগ করতে হয় (নতুন ক্লায়েন্ট মানে নতুন ডিপ্লয়), অথবা ধীর REST API দিয়ে যেতে হয়।
- পথ খোলা রাখতে সব কোয়েরি একটা ডাটা-লেয়ার দিয়ে যাবে, যেটা `shop_id` নেয়। পরে ক্লায়েন্টপ্রতি ডাটাবেসে গেলে শুধু ওই লেয়ার বদলাতে হবে।

**ক্লায়েন্টের ডাটা আলাদা রাখার নিয়ম:** `shop_id` কখনো রিকোয়েস্ট থেকে নেওয়া হবে না, শুধু লগইন সেশন থেকে। একজন ক্লায়েন্টের ডাটা আরেকজন দেখতে পাচ্ছে কি না, তার টেস্ট আলাদা করে লিখতে হবে।

## ৪. অ্যাডমিন প্যানেল (আপনার জন্য)

রোল: `super_admin` (আপনি), `owner`, `salesman`।

- **ক্লায়েন্ট তালিকা:** নাম, ধরন (ফার্মেসি/গ্রোসারি/রেস্টুরেন্ট), অবস্থা (চালু/বন্ধ), শেষ লগইন, বিলের সংখ্যা
- **নতুন ক্লায়েন্ট খোলা:** দোকানের নাম ও ধরন, মালিকের নাম ও অস্থায়ী পাসওয়ার্ড (প্রথম লগইনে বদলাতে হবে), মডিউল বেছে নেওয়া (ব্যাচ-মেয়াদ, ওজনে বিক্রি, রেসিপি)
- **অ্যাকাউন্ট বন্ধ বা চালু করা:** বকেয়া থাকলে বন্ধ। বন্ধ হলে ডাটা মুছবে না, শুধু লগইন আটকাবে
- **মেয়াদ ও প্যাকেজ:** কবে পর্যন্ত চালু, মেয়াদ শেষের আগে সতর্কতা
- **পাসওয়ার্ড রিসেট** (মালিক ভুলে গেলে)
- **ব্যাকআপ:** ক্লায়েন্টপ্রতি ডাটা নামানো (JSON/CSV), ব্যাকআপ থেকে ফেরত আনা
- **অডিট লগ:** অ্যাডমিন কখন কী করেছে, সব জমা থাকে
- **ক্লায়েন্টের ডাটায় ঢোকা:** ডিফল্টে নয়। দরকার হলে ক্লায়েন্টের অনুমতি নিয়ে সীমিত সময়ের জন্য, আর লগে লেখা থাকবে।

## ৫. প্রিন্ট: যেকোনো প্রিন্টারে

ক্লায়েন্টের পিসিতে প্রিন্টার অপারেটিং সিস্টেমে ইনস্টল থাকলে ব্রাউজার সেটাতেই ছাপতে পারে। আলাদা প্রিন্টার ড্রাইভার বা প্রোগ্রাম আমাদের লাগবে না।

- বিল চাপলে ছোট একটা লুকানো `iframe`-এ শুধু রসিদের HTML তৈরি হবে, তারপর `print()` চলবে। পুরো অ্যাপ ছাপা হবে না।
- **দুই ধরনের টেমপ্লেট:**
  - থার্মাল রসিদ (৫৮ বা ৮০ মিমি): CSS-এ `@page { size: 80mm auto; margin: 0 }`
  - A4 ইনভয়েস (বড় লেনদেন, ভ্যাটের কাগজ)
- **প্রতিটা দোকানের সেটিংস:** কাগজের মাপ, দোকানের নাম, ঠিকানা, ফোন, ট্যাক্স নম্বর, লোগো, রসিদের নিচের লেখা।
- **বাংলা ঠিকমতো ছাপা হয়**, কারণ ব্রাউজার লেখাকে ছবির মতো ছাপে। (ESC/POS কমান্ডে সরাসরি থার্মাল প্রিন্টারে পাঠালে বাংলা ফন্ট নিয়ে ঝামেলা হয়।)
- **প্রতিবার প্রিন্ট ডায়ালগ এড়াতে:** ক্রোম একটা শর্টকাটে `--kiosk-printing` চালু করলে ডিফল্ট প্রিন্টারে সঙ্গে সঙ্গে ছাপে। এটা ক্লায়েন্টের পিসির সেটআপে একবার করে দিতে হবে।
- **APK-এর জন্য:** প্রিন্টিংকে একটা `PrintService` ইন্টারফেসের পেছনে রাখুন। ব্রাউজারে `BrowserPrint`, APK-তে পরে ব্লুটুথ থার্মাল প্রিন্টারের আলাদা বাস্তবায়ন।

## ৬. D1-এর জন্য ডাটাবেসে যা বদলাতে হবে

**ক) আইডি:** সব টেবিলে টেক্সট আইডি (ULID), অ্যাপেই তৈরি। এতে একটা `db.batch()`-এর ভেতর এক স্টেটমেন্ট আরেকটার আইডি আগে থেকে জানে, আর অফলাইন ডিভাইসেও আইডি বানানো যায়।

**খ) টাকা ও দাম পূর্ণসংখ্যায়:** SQLite-এ দশমিক সংখ্যা ভাসমান (float), হিসাবে ভুল জমে। তাই:
- মোট টাকা: পয়সা, `INTEGER`
- ছোট একক প্রতি দাম (যেমন গ্রাম প্রতি ০.০৬৫ টাকা): ১/১০০০০ টাকার একক, `INTEGER`
- স্টকের পরিমাণ: ছোট এককে `INTEGER` (পিস, গ্রাম, মিলি)

**গ) নেতিবাচক স্টক আটকানো ও লেজার অপরিবর্তনীয় রাখা ট্রিগার দিয়ে:**

```sql
-- স্টক শূন্যের নিচে নামবে এমন বিক্রি আটকায় (অফলাইন সিংকে allow_negative = 1)
CREATE TRIGGER sm_guard BEFORE INSERT ON stock_movements
WHEN NEW.allow_negative = 0 AND NEW.qty < 0
 AND (SELECT COALESCE(SUM(qty), 0) FROM stock_movements WHERE batch_id = NEW.batch_id) + NEW.qty < 0
BEGIN SELECT RAISE(ABORT, 'insufficient stock'); END;

CREATE TRIGGER sm_no_update BEFORE UPDATE ON stock_movements
BEGIN SELECT RAISE(ABORT, 'stock_movements is append-only'); END;
CREATE TRIGGER sm_no_delete BEFORE DELETE ON stock_movements
BEGIN SELECT RAISE(ABORT, 'stock_movements is append-only'); END;
```

**ঘ) একটা বিক্রির ধাপ (FEFO) Worker-এ:**
1. FEFO ক্রমে ব্যাচ ও স্টক পড়া (মেয়াদোত্তীর্ণ বাদ)
2. কোড থেকে ঠিক করা কোন ব্যাচ থেকে কত
3. একটা `db.batch([...])`: বিল, বিলের আইটেম, স্টক লেজারের লাইন, মোট দাম
4. ধাপ ১-৩-এর মাঝে অন্য কেউ স্টক নিয়ে ফেললে ট্রিগার ব্যাচটা পুরোই বাতিল করে, তখন একবার নতুন করে চেষ্টা
5. `sales.client_uuid UNIQUE` ভাঙলে আগের বিলটাই ফেরত দেওয়া (দুবার জমার প্রতিরোধ)

**ঙ) গতির জন্য:** স্টকের যোগফল প্রতিবার লেজার থেকে না বের করে একটা `batch_stock` টেবিল রাখা, যেটা ট্রিগারে হালনাগাদ হয়। ছোট দোকানে প্রথমে দরকার নেই, ডাটা বাড়লে যোগ করা যাবে।

**চ) D1-এর সীমা:** প্রতি কোয়েরিতে সর্বোচ্চ ১০০ বাইন্ড প্যারামিটার। বড় বিল বা আমদানি টুকরো করে পাঠাতে হবে।

## ৭. ব্যাকআপ

- D1-এর পয়েন্ট-ইন-টাইম রিস্টোর (Time Travel) আছে, যা দিয়ে কয়েকদিন আগের অবস্থায় ফেরা যায়।
- তার ওপর Cron Trigger দিয়ে রোজ রাতে ক্লায়েন্টপ্রতি ডাটা R2-তে JSON হিসেবে জমা, যাতে অ্যাডমিন প্যানেল থেকে একজন ক্লায়েন্টের ডাটা আলাদাভাবে ফেরত আনা যায়।
- ক্লায়েন্টের "আমার সব ডাটা Excel-এ নামান" বোতাম।
- ফেরত আনার প্রক্রিয়া মাসে একবার পরীক্ষা করুন। না পরীক্ষা করা ব্যাকআপ ব্যাকআপ নয়।

## ৮. নিরাপত্তা

- পাসওয়ার্ড হ্যাশ: Worker-এর Web Crypto দিয়ে PBKDF2 (ইটারেশনের সীমা Cloudflare-এর ডকুমেন্টে দেখে নিন)
- সেশন: `HttpOnly`, `Secure`, `SameSite` কুকি
- লগইনে রেট লিমিট (ভুল পাসওয়ার্ডের চেষ্টা সীমিত), প্রয়োজনে Turnstile
- API কী, সিক্রেট `wrangler secret` দিয়ে, রিপোজিটরিতে নয়
- ক্লায়েন্টের ডাটা আলাদা কি না, তার স্বয়ংক্রিয় টেস্ট
- সব ইনপুট `zod` দিয়ে যাচাই

## ১১. খোলা প্রশ্ন

- **ভ্যাট ও বিলের নম্বর:** আইনি নিয়ম হিসাবরক্ষকের কাছে জেনে নিন।
- **ক্লায়েন্টদের কাছে কীভাবে টাকা নেবেন:** মাসিক নাকি বার্ষিক, আর পেমেন্ট কীভাবে ট্র্যাক হবে। প্রথমে হাতে (অ্যাডমিন প্যানেলে "মেয়াদ বাড়ান" বোতাম) রাখাই সহজ।
- **ক্লায়েন্টের ডাটার মালিকানা ও গোপনীয়তা:** ক্লায়েন্টকে কী কথা দিচ্ছেন (ব্যাকআপ, ডাটা মোছা, বন্ধ হলে কী হবে), সেটা একটা সাধারণ শর্তে লিখে রাখুন।
- **প্রথমে কোন প্রযুক্তিতে ফ্রন্টএন্ড:** React বা Svelte। আপনি যেটা জানেন সেটাই নিন।
